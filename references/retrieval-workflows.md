# 文件类型路由与三种检索流程

目标是在不做全库内容分析的前提下尽快回答当前问题。始终先用目录名、文件名、扩展名、缓存意图和轻量元数据判断候选；只有初步相关的文件才读取内容。目录意图由目录名称、路径层级、候选子文件名称及少量代表性证据综合推断，不能仅因目录中存在一个命中词就把整棵目录判为相关。

## 文件类型路由

| 类型 | 首选定位 | 局部意图识别 | 定位信息 |
|---|---|---|---|
| Markdown、TXT、日志、代码、配置 | `rg -n` 搜索原词与扩展词 | 每个命中点附近 200–500 个 Unicode 字符；按段落、标题、函数或配置块边界截取 | 行号、标题、函数名或字段路径 |
| JSON、YAML、XML、CSV/TSV | 先搜键名、列名和精确值 | 截取完整对象、节点或相关行；表格优先表头加命中行，不默认读取整表 | 字段路径、节点、行号 |
| DOCX、PPTX、EPUB | 优先复用 xunxu 缓存；否则只用本地已有安全读取能力 | DOCX 按段落/标题，PPTX 按页，EPUB 按章节；每块 200–500 字符 | 段落、标题、幻灯片号、章节 |
| XLSX | 优先工作表名、表头和缓存 | 只读相关工作表的表头与命中附近有限行列，不默认加载全工作簿 | 工作表、单元格或行列 |
| PDF | 优先 xunxu 的页码证据或本机已有文本层工具 | 按命中页截取文本块，每个文件最多 5 个代表性页/块；扫描件无文字层时报告盲区 | 页码和页内短摘要 |
| 图片 | 文件名、目录意图、xunxu OCR/视觉缓存 | 有有效缓存则复用；否则仅在现有视觉/OCR 能力可用时识别与当前方向有关的文字或画面 | 图像区域或 OCR 文字摘要 |
| 音频 | 文件名、时长、xunxu 转写缓存 | 仅复用有效转写或使用现有本地转写能力；按时间戳截取相关转写块 | 时间戳 |
| 视频 | 文件名、时长、xunxu 转写/关键帧缓存 | 有效转写优先；否则综合 5%–95% 时间线的多张关键帧。关键帧路径不是内容结论 | 时间戳、帧时间 |
| 压缩包、安装包、未知二进制 | 文件名、扩展名、大小、时间等元数据 | 不执行、不解压、不挂载；没有安全读取能力时不做内容意图判断 | 元数据 |

通用内容块规则：同一文件同一轮最多保留 5 个不重复块，每块 200–500 个 Unicode 字符。以命中点为中心并尽量对齐语义结构；块重叠或相距不足 100 字符时合并。优先选择覆盖不同关键词、章节或观点的块。片段仅用于相关性判断，关键结论必须补读完整语义单元核验。

## 场景一：首次检索，尚无 `.cache`

1. 从用户问题生成一个简短检索方向、精确实体、同义词、缩写、中英文写法和时间条件。
2. 检查目标根目录；确认没有 `.cache` 后立即运行 `cache_manager.py init`，只初始化空机器缓存和可读索引，不做全库内容分析。
3. 使用 `rg --files` 盘点目录和文件类型并排除 `.cache`。先根据目录名、文件名、扩展名、路径层级和轻量元数据形成初步目录/文件意图。
4. 对与检索方向明显不符的目录和文件停止在元数据层，不读取正文，也不为了“缓存完整”而补做分析。
5. 对候选文本文件用 `rg` 定位；其他格式按上表路由。每个候选文件最多读取 5 个 200–500 字符块，判断“相关、可能相关、不相关”。
6. 只对实际读取过的相关或可能相关文件写入带 `direction` 的抽丝缓存。不相关结论只有在证据足够时才缓存，不能仅凭扩展名缓存为不相关。
7. 先回答用户，再沿高价值块中的新实体、链接、编号或日期最多扩展两轮。没有新高价值材料时停止，不等待整库建索引。

结果：首次响应只承担“当前问题所需的最小分析成本”；缓存随真实问题逐步生长。

## 场景二：用户重复提问，已有抽丝缓存

1. 读取 `.chousi.intent.json` 和抽丝管理的可读索引，从新问题生成检索方向与关键词。
2. 先用缓存的目录/文件意图筛候选，再对候选及本次新增的文件名命中项运行 `inspect --direction ...`。不要为无关文件计算内容意图。
3. 按状态处理：`fresh-covered` 直接复用；`fresh-uncovered` 定向读取新方向所需的局部块；`stale` 重新读取当前版本；`uncached` 按首次候选流程读取；`missing` 只报告并保留旧记录。
4. 文件改变时不能沿用旧证据支撑结论。新指纹记录通过 `supersedes` 指向旧指纹；同一指纹的新方向追加到 `directions`，不得覆盖其他方向。
5. 将新证据增量写入抽丝缓存并刷新抽丝索引；答案注明使用了哪些缓存、重新读取了哪些文件以及仍未覆盖的格式盲区。

## 场景三：目录已由 xunxu 整理并存在其 `.cache`

1. 即使没有 `.chousi.intent.json`，也先读取 xunxu 的 `file2intent.md`、`.organizer.intent.json` 和 `.organizer.state.json` 形成候选；媒体问题再按需读 `.organizer.raw-analysis.json`，能力判断按需读 `.organizer.dependencies.json`。
2. 使用 `.organizer.state.json` 解析整理后的当前路径，并以实际文件重新计算 `v2` 指纹。路径、指纹和实际文件必须对应；旧路径或旧指纹只能作为线索。
3. 若 xunxu 意图缓存指纹有效且语义足以覆盖当前问题，可直接作为候选意图和初步证据；若它只有通用分类/命名意图，没有当前方向所需证据，则读取相关原文件的局部块。
4. xunxu 缓存过期时，不修改 `.organizer.*`、`runs/` 或其 `file2intent.md`。重新读取实际文件后，只把最新指纹、当前方向和短证据写入 `.chousi.intent.json` 与抽丝自己的索引。
5. xunxu 的转写、OCR 或关键帧缓存可按指纹复用；`installation-required`、临时错误、待分析状态及未经视觉归纳的帧路径不能作为有效内容结论。
6. 后续提问转入“场景二”，同时仍可把有效 xunxu 缓存作为补充候选源。

三种场景都不得因初始化、校验或更新缓存而修改、移动、重命名或删除知识库中的任何既有文件和目录。
