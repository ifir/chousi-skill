# 文件读取路由

只在候选文件与当前检索方向相关、且有效缓存不足时读取正文。优先调用 `scripts/extract_text.py` 返回不超过 5 个局部片段；不要把全文打印到终端。

## 文本、代码与结构化文本

先用 `rg -n` 定位，再读取 200–500 个 Unicode 字符。JSON/YAML/XML 尽量补齐对象、节点或字段路径；CSV/TSV 保留表头和命中行。

## Office 与 EPUB

- DOCX：按段落、标题或 OOXML 部件定位。
- PPTX：按幻灯片 XML 定位，答案标注页码；同页文本需要按视觉结构复核时再读取页面。
- XLSX：先读工作表名、表头和少量预览；定位后只取命中行列。用户要求统计分析时才使用 pandas/openpyxl 做过滤或聚合，不因普通检索加载整表。
- EPUB：只检索章节文本，避免把二进制资源当正文。

## PDF

1. 先判断是否有文本层。优先使用已安装的 `pdftotext`，输出必须写到系统临时文件，禁止 stdout。
2. 没有 `pdftotext` 时使用已有的 pypdf 逐页提取；每次只返回命中页片段。
3. 需要表格时才升级到 pdfplumber；普通问答不默认提取全部表格。
4. 文本层为空才考虑 OCR。没有现成 OCR 或页面渲染能力时报告盲区，不自动安装依赖。
5. 加密、损坏或无法提取时不猜测。

## 图片、音频和视频

优先复用指纹有效的 xunxu OCR、转写与关键帧缓存。图片可使用环境已有视觉能力；音频按时间戳截取转写；视频先用有效转写，没有有效语音时才综合多张关键帧。仅有帧路径不等于已有结论。

## 压缩包、安装包和未知二进制

仅使用文件名、扩展名、大小和修改时间等元数据。不执行、不解压、不挂载、不安装。
