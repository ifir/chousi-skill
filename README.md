# chousi-skill（抽丝）

“抽丝”是一个 Codex Skill：不依赖 RAG 或向量数据库，直接在获准访问的本地知识库、项目文档、笔记和代码中，通过关键词扩展、文件关联与证据回溯逐层检索，输出可复查的答案。

它不会先把整个目录全部读完，也不会为了建立完整索引拖慢首次回答。抽丝围绕用户当前问题筛选候选，默认找到一条经过上下文核验、足以回答问题的高置信度证据后立即返回；用户不满意或明确要求深度搜索时，再扩展到剩余目录和格式。

## 主要特点

- **问题驱动**：先生成检索方向、3–8 个核心词和扩展词，再判断哪些目录和文件值得读取。
- **渐进读取**：先路径与缓存、再关键词定位、再局部内容块，最后才补读完整语义单元核验。
- **快速与深度双模式**：快速搜索优先响应；深度搜索覆盖其余可读范围、冲突和格式盲区。
- **方向化缓存**：同一文件可以缓存多个问题方向；文件未变但方向未覆盖时，只补读新方向。
- **缓存可验证**：用大小、纳秒修改时间和首尾采样内容生成文件指纹，避免过期证据继续生效。
- **与 xunxu 协同**：复用有效的文件意图、当前位置、OCR、转写和关键帧缓存，但不修改 xunxu 的 `.organizer.*` 文件。
- **严格只读**：不重命名、移动、删除、覆盖、整理、执行、解压或挂载知识库文件；只写抽丝自己的 `.cache`。
- **证据可追溯**：答案标注绝对路径和行号、页码、工作表、单元格、章节或时间戳。

## 能做什么

- 从自然语言问题提取关键词、同义词、实体和时间线索；
- 从一次命中继续追踪链接、引用、版本、编号和关联文件；
- 综合跨文件证据，区分事实、推论、冲突和未知项；
- 用绝对文件路径和行号标注来源；
- 严格只读知识库，绝不改名、移动、删除或修改已有文件；
- 每次检索优先复用目标目录中的 `.cache`，按文件指纹检查过期并增量刷新；
- 缓存格式与 xunxu-skill 保持同类结构，同时使用 `.chousi` 前缀避免覆盖其它工具缓存；
- 兼容 xunxu 的 OCR、转写、视频关键帧及组合证据缓存，并读取依赖评估识别能力盲区；
- 按文件类型进行局部意图识别，每个候选文件每轮最多读取 5 个、每块 200–500 字符；
- 区分首次检索、重复提问和复用 xunxu 缓存三种流程，缓存按检索方向增量生长；
- 默认找到一个足以回答问题的高置信度匹配后立即停止，并披露已命中、已搜索无匹配和未搜索目录；用户不满意时再升级为全面搜索；
- 每个检索方向最多迭代 5 轮，按文件结构渐进读取；PDF 文本先落临时文件再局部检索，Excel 先探查工作表和表头；
- 优先沿 `.cache` 中的文件意图与路径信息进入最相关目录，不把导航索引当成最终证据；
- 全程在本地完成检索，也不把知识库上传到外部服务。

## 只读边界与缓存

抽丝对知识库正文只有读取权限，不执行文件整理。唯一允许的写入是检索根目录的 `.cache`：不存在时初始化，存在时先核对机器缓存、可读索引与实际文件。文件大小、纳秒修改时间或首尾采样内容发生变化时，抽丝重新读取相关文件并增量更新缓存；指纹未变化时直接使用缓存。

机器缓存保存于 `.cache/.chousi.intent.json`，可读索引通常保存于 `.cache/file2intent.md`。如果该索引已经由其它工具维护，则抽丝改用 `.cache/.chousi.file2intent.md`，不会覆盖已有缓存。

缓存状态分为：`fresh-covered`（可直接复用）、`fresh-uncovered`（文件未变但需要补充当前方向）、`stale`（文件已变化）、`uncached`（没有缓存）和 `missing`（缓存记录对应文件已不存在）。

## 总体检索流程

1. 确定检索根目录并检查 `.cache`。
2. 从问题生成检索方向、关键词、同义词、缩写、实体、日期和编号。
3. 用缓存意图、目录名、文件名、扩展名和轻量元数据给候选排序。
4. 重新计算候选文件指纹，判断缓存是否最新、是否覆盖当前方向。
5. 对必须读取的文件，按文件类型定位并提取局部内容。
6. 每个内容块控制在 200–500 个字符，同一文件同一轮最多 5 块。
7. 从命中内容提取新实体和关联文件，最多迭代 5 轮。
8. 回到完整段落、页面、对象、表格行列或相邻结构核验关键结论。
9. 输出答案、来源、已搜索范围和格式盲区，再增量更新抽丝缓存。

## 不同文件类型的检索流程

### Markdown、TXT、日志和代码

先根据路径、文件名和扩展名筛选候选，再用 `rg -n` 搜索精确实体、原词及扩展词。命中后读取附近 200–500 个字符，并尽量对齐标题、段落、函数或代码块边界。同一文件每轮最多保留 5 个去重片段。相关片段用于判断当前方向的文件意图和生成新线索；关键结论必须回到完整段落或函数核验，并记录行号或符号名。

### JSON、YAML、XML 和配置文件

优先搜索键名、字段路径、精确值、接口路径和配置项。命中后补齐所在对象、数组元素、XML 节点或配置块，避免孤立解释一行。检索会区分“字段存在”“字段已启用”和“配置当前生效”，不会仅凭静态映射推断运行状态。来源使用字段路径、节点范围或行号。

### CSV 和 TSV

先读取表头，将用户问题映射到相关列，再搜索精确值和关键词。只读取表头、命中行及必要的相邻行，保留列名与值之间的对应关系。只有用户要求统计分析时，才执行过滤、分组或聚合；普通检索不加载整张表。

### DOCX

先用文件名、缓存意图和文档属性筛选候选，再从 OOXML 中按标题、段落和表格提取可读文本。关键词命中后只返回附近段落或相关表格行。结论标注文档标题、段落或表格位置；文本提取不完整时明确报告格式限制。

### PPTX

按幻灯片提取标题、正文、图表文字和可读备注，再用关键词定位页面。同一演示文稿最多保留 5 个代表性页面或片段。若文本顺序无法表达版面关系，再查看对应页面的视觉结构。答案以页码定位，不把不同页面的指标误拼成同一事实。

### XLSX

先读取工作表名称、表头和少量预览行，判断工作簿用途以及相关字段；然后定位命中单元格，只读取表头、命中行和必要的相邻行列。答案保留工作表名、单元格或行列定位。用户明确要求计算时，才使用 openpyxl/pandas 做过滤、分组或聚合，不因普通问答加载整个工作簿。

### EPUB

先根据书名、作者、目录和章节名筛选候选，再只检索 EPUB 内的章节 HTML/XHTML 文本，忽略图片、字体等二进制资源。命中后截取局部段落并用章节定位；宽泛主题只选择最相关章节，不默认通读整本书。

### PDF

先判断是否存在文本层。优先调用本机已有的 `pdftotext`，将结果写入系统临时文件后再搜索，禁止把全文输出到终端；没有该工具时使用已有的 pypdf 逐页提取。命中后只返回相关页的有限片段，需要布局或表格时才升级到 pdfplumber。文本层为空才考虑 OCR；缺少 OCR 或页面渲染能力时报告盲区，不自动安装依赖。加密、损坏或提取失败时不猜测。

### 图片

先检查文件名、所在目录和 xunxu 的 OCR/视觉缓存。指纹有效且覆盖当前方向时直接复用；缓存不足时才使用环境已有的图像理解或 OCR 能力识别相关文字、界面和主体。缓存只保存主题和短证据摘要，不保存大段 OCR 原文。图片模糊、裁剪或证据不足时降低置信度。

### 音频

先检查文件名、时长、媒体元数据和 xunxu 转写缓存。有效转写按关键词和时间戳搜索，每个命中只截取有限相邻语句。没有缓存时，仅在本地已有转写能力的情况下处理，不自动安装模型，也不上传音频。无转写能力、音质不足或没有有效语音时列为内容盲区。

### 视频

先检查文件名、时长、媒体元数据以及转写或关键帧缓存。有有效转写时优先按时间戳搜索；没有有效语音时才综合覆盖视频 5%–95% 时间线的多张代表性关键帧。不能只看封面或首帧，“已经抽帧”也不等于“已经获得内容结论”。音轨和画面可以组合为证据；缺少两种能力时仅检查名称和元数据，并报告盲区。

### 压缩包、安装包和未知二进制文件

仅检查文件名、扩展名、大小、修改时间和安全可读的元数据。不执行、不解压、不挂载、不安装。元数据不足以判断内容时明确标为未知，不根据名称强行推断。

## 三种缓存场景

### 首次检索，没有 `.cache`

只初始化空缓存，不做全库内容分析。先从当前问题筛选相关候选，读取足够证据后快速返回，缓存随真实问题逐步增长。

### 重复提问，已有抽丝缓存

先用缓存筛选候选并重新计算实际文件指纹。覆盖当前方向且未过期的记录直接复用；新方向或过期文件只增量读取必要内容。同一文件可以保存多个检索方向。

### 目录已由 xunxu-skill 整理

优先读取 xunxu 的文件意图、整理后路径、OCR、转写和关键帧缓存，再与实际文件指纹核对。缓存过期或方向不足时读取原文件，并只更新抽丝自己的缓存。

## 安装

在 Codex 对话中直接说：

```text
给我安装 https://github.com/ifir/chousi-skill 这个 Skill
```

安装完成后，在下一轮对话中即可使用。

## 使用

可以显式调用：

```text
使用 $chousi 在 /path/to/knowledge-base 中查找关于“项目定价调整”的资料，给出结论、证据和仍不确定的地方。
```

也可以直接提出适合本地检索的问题，例如：

```text
帮我从本地会议纪要里梳理这个决策是怎么形成的，并标出关键来源。
```

直接要求深度搜索：

```text
使用 $chousi 深度搜索所有与 HN 版 IMLP 咨询页有关的本地资料，不要遗漏其他目录。
```

## 输出内容

抽丝的回答通常包括直接结论、关键证据、可点击的本地文件路径和具体定位，并区分材料明确陈述的事实、跨文件推导、冲突信息和未知项。快速搜索还会披露找到匹配、已搜索无匹配和未搜索目录；深度搜索则报告完整覆盖范围以及无法读取的文件类型。
